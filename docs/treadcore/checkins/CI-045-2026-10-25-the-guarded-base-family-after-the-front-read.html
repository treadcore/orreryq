Abstract

CI-044 found the a-raid-on-a-guarded-base family under its floor (70.2% against 75%) and bisected the drop to 5899e8e, which set the front read's three weights to 0 by default. That commit gave the front scenario its old w_front back so the scenario still tested the front read. It missed this family, whose header names w_front_push as its mechanism. By a rule written before the run, the family now sets w_front_push to its old 0.75 and reads 81.5% +/- 1.9% (326 of 400), close to the 81.8% it read before 5899e8e. Every family holds and the brain's 87 tests pass. The defaults are unchanged.

Index terms: scenario families, regression, test fixtures, defaults.

III. Methods

IV. Results

In LR 80: the family at 326 of 400, 81.5% +/- 1.9%, floor 75% (281 of 400, 70.2%, without the weight); every other family as before; 87 tests passed.

V. Discussion

A scenario that tests a mechanism has to keep the mechanism on when a default turns it off. 5899e8e did that for the scenario it knew of and missed the family. The rule CI-044 added to CLAUDE.md (make families at each default change) would have caught it on that commit. The fix is in the test, not the brain: the push point is still off for play.
